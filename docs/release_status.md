# Release status — 13 September 2026

## Manuscript-aligned implementation

The default implementation follows the current CGDD-Net manuscript architecture and confirmed settings:

- one grayscale input channel;
- encoder widths 8, 16, 32, 64, 128;
- shared detail width 8;
- four CSDE attention heads with base spacings 1, 3, 5, and 7;
- dense SAMG branches with kernel sizes 1, 3, 5, and 7;
- DCDF fusion of E2/E3/E4 detail features;
- shared detail guidance at D3/D2/D1;
- direct skips at E4 and E1;
- one CCA block after D3 fusion;
- FOV-masked BCEWithLogits loss;
- Adam with base learning rate 0.001;
- overlapping-patch probability averaging for inference.

The complete model contains **1,956,802 trainable parameters (1.96 M)**.

## Functional validation

The repository test suite and synthetic end-to-end smoke test verify software behavior, including:

- forward and backward execution for all seven cumulative ablations;
- offset and adaptive-gating gradient flow;
- output-size preservation for odd and small inputs;
- FOV-aware metrics and image-level aggregation;
- overlapping-patch probability averaging;
- learning-rate scheduler state handling;
- checkpoint serialization and same-run resume;
- saved-checkpoint inference and metric export.

The GitHub Actions workflow is configured to run CPU checks on pushes and pull requests. These software checks complement, rather than replace, the retinal benchmark experiments reported in the manuscript.

## Experimental and software environments

The author-reported experiment environment is NVIDIA H200 141 GB, PyTorch 2.13.0, and CUDA 13.2.

Repository CI and local smoke testing may use different CPU/PyTorch versions; these checks validate implementation behavior rather than benchmark performance.

## Complexity reporting

The implementation's parameter count is measured directly from the registered model parameters and is **1,956,802** for the default full model.

`docs/profile_measured.json` also records supported-operation estimates for selected input sizes together with unsupported operators. These partial counts are retained as implementation diagnostics and are not presented in the manuscript as complete FLOP totals or hardware latency measurements.

## Reproducibility records for new runs

A new training run stores:

- resolved configuration;
- environment metadata;
- copied train/validation manifests and hashes;
- training history;
- best/latest checkpoints;
- best validation AUC and training summary.

Evaluation can export per-image metrics, probability maps, binary predictions, and run provenance. Dataset split validation checks case identity, subject identity where available, file paths, and duplicate image content before patch sampling.

## Source and attribution

The executable CGDD-Net package is self-contained. Upstream workflow attribution is documented in `NOTICE`; relevant license material is retained under `LICENSES/`. Dataset images are not redistributed by this repository and remain subject to the original providers' terms.
