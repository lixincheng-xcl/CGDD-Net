# “长期有效归档地址”是什么意思

它就是一个稳定的下载链接，让审稿人和读者在以后仍能找到产生论文结果的那一版材料。只有一个会不断修改的仓库首页，还不足以准确指出实验使用的是哪个版本。

最直接的做法是在 GitHub 仓库创建固定版本的 Release，例如作者自行决定的版本号，并附上相应材料。需要更长期的存档时，也可以把该版本存入能提供持久标识符的研究数据仓库。这里没有替你创建线上发布，也没有生成或杜撰 DOI。

## 应归档哪些文件

1. **最终模型配置**：模型代码的提交编号，网络通道和注意力设置，预处理、图像块尺寸、Adam 学习率、warmup 和重启周期、批量大小、训练轮次、随机种子、推理阈值等。当前训练程序会保存 `config.json` 和 `environment.json`。
2. **数据划分清单**：每个数据集哪些原始图像用于训练和测试；五折实验则每折保存相应名单。只需图像标识和相对路径，不必把受原始许可约束的数据集重新上传。本项目的 manifest 机制可用于保存新运行的数据划分。
3. **实验输出**：实际训练的日志与检查点、每张图的指标 CSV、汇总 JSON，以及计算论文统计表所用的原始统计样本。体积较大的权重和概率图可作为 Release 附件或另行存档。
4. **完整性记录**：文件 SHA-256、代码版本、运行命令和环境版本，用来确定读者取得的是哪一份文件。

## 当前论文与仓库已同步的内容

当前公开实现与论文的核心结构和配置已同步：单通道灰度输入、编码通道 `8/16/32/64/128`、共享细节宽度 8、CSDE/SAMG/DCDF、共享细节解码、选择性跳跃连接以及 D3 融合后的单个 CCA。论文参数量为 1,956,802（约 1.96 M），基础学习率为 0.001，损失为 FOV-masked BCEWithLogits；训练使用 64×64 图块，推理使用 96×96 图块、stride 16，并在重叠区域平均概率后以 0.5 阈值二值化。

论文数据协议为 DRIVE 20/20、CHASE_DB1 20/8、STARE 五折评估以及 HRF 25/20。论文 Table 7 采用 AUC 均值 ± 标准差并使用 Wilcoxon rank-sum test；Table 10 报告完整模型 1.96 M 参数量以及固定复杂度比较配置下的 29.96 GFLOPs。`docs/profile_measured.json` 中保存的部分算子计数仍作为公开实现的诊断信息，不将其视为另一套完整 FLOP 结果或硬件时延。

`results/` 中的主结果、消融结果和跨数据集结果已经按最终论文表格同步。新训练产生的输出与这些论文结果转录分开保存，不会覆盖论文数值。

若后续创建固定 GitHub Release，建议将最终提交版本对应的源码、数据划分清单（若可公开）、运行配置、统计原始数据和必要的检查点一并归档。若部分材料不能公开，则在论文或 Release 中明确说明可获取范围及实际原因。
